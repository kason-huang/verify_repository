# Astra 视频监控评测

依赖 Python 3.10+、Pillow、FFmpeg、FFprobe，以及已登录并可使用 `gpt-6-astra` 的 Codex CLI。需要本机允许 Codex 访问账户和网络。评测调用中关闭工具与网络搜索。

```sh
python3 video_eval/run.py
```

默认输入 `videos/box_pick_right_cam_high_5_episodes/episode_000000.mp4` 至 `episode_000004.mp4`。可用 `--ffmpeg` 和 `--ffprobe` 指定可执行文件。输出目录默认是 `results/video-astra-v1`，另起一轮时用 `--output` 指定新目录。

离线评测默认预热。五个会话各先发一条纯文本请求，全部返回后再开始视频判断。每段的首条日志分别记录会话创建、预热请求、正式视频请求的耗时，以及从会话创建到正式请求前的总等待。用 `--no-warmup` 可运行未预热的对照。

```sh
python3 video_eval/serve.py
```

打开 [本地监控页面](http://127.0.0.1:8765/) 查看本轮结果。页面约每秒刷新一次，运行中可以看最新判断，也可以切换 episode 并跟随视频播放。点击时间线跳到相应判断，点击证据时间查看对应的原始画面。更换运行目录时，给 `serve.py` 传入相同的 `--output`。离线回放可在浏览器中打开输出目录的 `report.html`，保留视频及结果目录的相对位置即可。

打开 [实时试跑](http://127.0.0.1:8765/live)，选择 episode 和模型，点击「开始监控」，页面就会启动一个新会话。视频按原速播放，只有播过的窗口才会排队。模型一次处理一个窗口。暂停会暂缓加入新窗口，已经加入的窗口仍会继续处理。页面分别显示排队和推理耗时。每次试跑写入输出目录的 `live-runs/<会话 ID>/`。试跑使用评测生成的抽帧索引，需要保留 `config.json` 和抽帧图。默认模型为 `gpt-6-astra`，可以通过 `serve.py --model <Codex 模型 ID>` 添加账户可用的其他模型。

点击「预热模型」会发送一条纯文本请求，期间可以挑选 episode。「开始监控」会在预热完成后使用同一会话播放并提交画面。也可以直接点击「开始监控」跳过预热。预热请求耗时和视频推理耗时分别显示。已预热的会话最多等待三分钟，超时后可重新预热。

每段使用一个独立 Astra 会话，按 3 秒窗口推进。对 30 fps 视频每隔 8 帧抽取一帧，并额外采样每个窗口的末帧。Astra 每次只收到当前窗口已有的画面和 LeRobot 原始任务指令，之前的窗口通过本段会话保留。时间戳从各自 episode 的起点算，判断时间是该窗口最后一帧的时间。回放以模型返回后一窗口为序推进，未模拟实时吞吐。`timeline.jsonl` 同时记录每次调用的墙钟耗时。

成功要看见右臂把一个盒子提离原支撑面。模型输出任务阶段、相对上次观察的变化、结果、是否需要干预和引用的画面。干预阈值是本轮的评测设定，例如三次明确抓取失败，或在可见失败后六秒未取得进展。完整规则和抽帧映射见 `config.json`。`summary.json` 和页面展示模型判断。计算正确率或干预召回率需要人工标注和对应的异常片段。
