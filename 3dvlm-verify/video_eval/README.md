# 视频监控评测

直接在浏览器打开仓库根目录的 [index.html](../index.html)，即可查看 Astra 和 MoTVLM 的离线报告，无需运行监控服务。

依赖 Python 3.10+、Pillow、FFmpeg 和 FFprobe。Astra 需要已登录且能使用 `gpt-6-astra` 的 Codex CLI，评测调用中关闭工具与网络搜索。MoTVLM 需要能访问 `image_eval/tasks.json` 中配置的推理服务。

```sh
python3 video_eval/run.py
```

默认输入 `videos/box_pick_right_cam_high_5_episodes/episode_000000.mp4` 至 `episode_000004.mp4`。可用 `--ffmpeg` 和 `--ffprobe` 指定可执行文件。输出目录默认是 `results/video-astra-v1`，另起一轮时用 `--output` 指定新目录。

Astra 离线评测默认预热。五个会话各先发一条纯文本请求，全部返回后再开始视频判断。每段的首条日志分别记录会话创建、预热请求、正式视频请求的耗时，以及从会话创建到正式请求前的总等待。用 `--no-warmup` 可运行未预热的对照。 加 `--serial` 可逐个发送 Astra 的预热和画面请求，上一条返回后才发送下一条。

```sh
python3 video_eval/run.py --model motvlm
```

MoTVLM 离线结果默认写入 `results/video-motvlm-v1`。使用与 Astra 一样的抽帧拼图，逐段串行请求。接口本身无会话，每次请求附带最近两条有效判断及首次成功记录，没有预热步骤。报告分别显示请求实际耗时和接口返回的服务端耗时。两种模型共享输出字段、证据编号和评分规则。

### MoTVLM 独立帧离线测试

用原拼图评测的 `config.json` 和已抽取的 JPEG 重跑同一批视频。每个窗口独立判断，按时间顺序发送当前窗口的原始抽帧。达到接口图片数量上限时，保留该窗口时间最晚的几帧。输出默认保存到 `results/video-motvlm-frames-no-history/`。复跑时可用 `--output` 指定新目录。

```sh
python3 video_eval/run.py --model motvlm --motvlm-frames-from results/video-motvlm-v1/config.json
```

打开离线首页的「MoTVLM 独立帧离线报告」，点击时间线后可以展开该次请求的全部输入帧。每次判定只对应当前窗口，整段任务是否成功需要结合时间线查看。
报告只将能精确对应到当前请求图片的数字帧号和时间戳转换为标准 ID，并去除重复引用。缺失字段会标为未提供，字段冲突会单独标记。完整判断统计只计入字段齐全且无冲突的响应。

查看报告和启动监控服务的命令见[仓库 README](../README.md#查看视频评测报告)。启动后，在[评测首页](http://127.0.0.1:8766/)的顶部导航栏选择 **Astra 离线报告**、**MoTVLM 离线报告**、**对比报告**或 **实时监控**。报告中可以切换 episode，点击时间线或证据时间跳到对应画面。更换报告目录时，分别用 `--output` 和 `--motvlm-output` 指定 Astra 和 MoTVLM 的输出目录。

打开[实时试跑](http://127.0.0.1:8766/live)，选择 episode 和 `gpt-6-astra` 或 `MoTVLM`，点击「开始监控」。视频按原速播放，只有播过的窗口才会排队。模型一次处理一个窗口。暂停会暂缓加入新窗口，已经加入的窗口仍会继续处理。页面分别显示排队和推理耗时，每次记录写入输出目录的 `live-runs/<会话 ID>/`。试跑使用评测生成的 `config.json` 和抽帧图。页面提供两种模型的离线报告入口，使用 `--motvlm-output` 可指定 MoTVLM 报告目录。如果 MoTVLM 服务正在运行离线评测，等离线结束后再启动同模型的实时试跑。

使用 Astra 时，点击「预热模型」会发送一条纯文本请求，期间可以挑选 episode。「开始监控」会复用预热后的会话。也可以直接点击「开始监控」跳过预热。预热和视频推理耗时分别显示。已预热的会话最多等待三分钟，超时后可重新预热。

每段使用一个独立 Astra 会话，按 3 秒窗口推进。对 30 fps 视频每隔 8 帧抽取一帧，并额外采样每个窗口的末帧。Astra 每次只收到当前窗口已有的画面和 LeRobot 原始任务指令，之前的窗口通过本段会话保留。时间戳从各自 episode 的起点算，判断时间是该窗口最后一帧的时间。回放以模型返回后一窗口为序推进，未模拟实时吞吐。`timeline.jsonl` 同时记录每次调用的墙钟耗时。

成功要看见右臂把一个盒子提离原支撑面。模型输出任务阶段、相对上次观察的变化、结果、是否需要干预和引用的画面。干预阈值是本轮的评测设定，例如三次明确抓取失败，或在可见失败后六秒未取得进展。完整规则和抽帧映射见 `config.json`。`summary.json` 和页面展示模型判断。计算正确率或干预召回率需要人工标注和对应的异常片段。
